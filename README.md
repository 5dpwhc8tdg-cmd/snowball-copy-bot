# Snowball Copy Bot

Бот следит за публичным портфелем **«Облигационные фантазии»** (snowball-income.com/public/portfolios/ukbRjaXjfg) и присылает в **Telegram** и/или **MAX** пуш о каждой новой сделке: что купили/продали, сколько, по какой цене, с каким НКД, сколько это стоило — плюс подсказки «а не падающая ли это бумага» и, при желании, пересчёт размера сделки под ваш капитал.

Написан на чистом Python 3.9+ (только стандартная библиотека — ничего ставить не нужно).

---

## 1. Что делает бот

- Раз в `POLL_INTERVAL` секунд (по умолчанию 5 минут) запрашивает у Snowball публичный список сделок портфеля.
- Сравнивает с тем, что уже видел (SQLite), и присылает только новое.
- Сделки, накопившиеся за интервал, приходят одним сообщением, чтобы не спамить.
- Для каждой бумаги подтягивает карточку: номинал, текущая цена в % от номинала, доходность к погашению, рейтинг — и предупреждает, если выпуск выглядит проблемным.
- Понимает команды в Telegram: `/status`, `/last`, `/mute`, `/unmute`, `/help` (только при запуске как постоянный процесс — в GitHub Actions слушателя команд нет).
- Работает без вашего аккаунта в Snowball: это публичные данные, авторизация не нужна.

Пример сообщения (это реальные сделки портфеля):

```
📊 Облигационные фантазии — новых сделок: 2
покупок 1 на 101 043,37 ₽ · продаж 1 на 66 870,42 ₽

🟢 ПОКУПКА — Спектр БО-02
RU000A10BQ03 · номинал 1000
100 шт × 989,50 ₽ (99,0% от номинала)
НКД: +20,34 ₽ / шт
Итого: 101 043,37 ₽
Комиссия: 59,37 ₽
↳ по вашему масштабу ×0.25: 25 шт ≈ 25 260,84 ₽
🕒 17.11.2026 МСК
🔗 карточка бумаги
ℹ️ Кредитного рейтинга нет → у брокера потребуется тест неквала.
```

## 1.1. Доступна ли бумага неквалу — в каждом сообщении

Раньше в уведомлении была общая фраза «рейтинга нет → нужен тест». Теперь бот для каждой сделки явно пишет вердикт, опираясь на два источника:

| Источник | Что берём | Зачем |
|---|---|---|
| **MOEX ISS** (`iss.moex.com/iss/securities/<ISIN>.json`, без токена) | `ISQUALIFIEDINVESTORS` (бумага только для квалов), `HASDEFAULT`, `HASTECHNICALDEFAULT`, `LISTLEVEL`, тип купона, дата погашения | официальные признаки выпуска от биржи |
| **Карта рейтингов** (публичная таблица облигаций smart-lab.ru) | кредитный рейтинг выпуска | именно рейтинг определяет, нужен ли неквалу тест |

Логика вердикта (правила ЦБ):

- рейтинг **A+ и выше** → «✅ НЕКВАЛУ МОЖНО БЕЗ ТЕСТА»;
- рейтинг ниже A+ или его нет → «⚠️ НУЖЕН ТЕСТ НЕКВАЛА» + напоминание про лимит 100 000 ₽;
- `ISQUALIFIEDINVESTORS = 1` и рейтинга ниже A+ → «⛔ ТОЛЬКО ДЛЯ КВАЛОВ»;
- для **продажи** вердикт отдельный: продать можно любую бумагу, бот лишь отмечает, понадобился ли бы тест для покупки.

Дополнительно в сообщение попадают: уровень листинга, технический дефолт/дефолт с MOEX, структура выпуска (оферта call/put, амортизация), тип купона.

Пример (реальная сделка):

```
🔴 ПРОДАЖА — СибСульфур БО-02-001P
RU000A10DDT6 · номинал 1000
⚠️ НУЖЕН ТЕСТ НЕКВАЛА — рейтинга A+ и выше нет
100 шт × 390,29 ₽ (39,0% от номинала)
Итого: 39 082,58 ₽
· уровень листинга 3 (3-й — вне котировальных списков)
· ⚠️ на MOEX зафиксирован ТЕХНИЧЕСКИЙ ДЕФОЛТ
· без теста неквал может купить максимум на 100 000 ₽ («право последнего слова»)
```

**Важные оговорки, которые бот тоже подчёркивает:**

- Это **ориентир, а не гарантия**. Окончательное решение принимает брокер в момент заявки: у БКС свои правила признания квалов и свои фильтры доступности. Бот не может «узнать в БКС» — у БКС API с признаком `for_qual_investor_flag` доступен только клиентам с торговым токеном БКС, а публичного веб-API для этого нет (сайт закрыт защитой от ботов). Если дадите токен БКС API — добавлю сверку с ним, тогда вердикт станет точным для БКС.
- **Осторожно с флоатерами.** Формально бумага с рейтингом A+ и выше покупается без теста, но по облигациям с переменным купоном у неквалов бывают отдельные ограничения ЦБ. Бот помечает такие выпуски (`купон: Ключевая ставка`), но если у вас нет теста — проверьте в приложении.
- Рейтинг smart-lab берётся «как есть» и кэшируется на 2 суток (полная карта ~900 выпусков собирается за ~18 секунд).

## 2. Быстрый старт (10 минут)

### 2.1. Telegram-бот

1. В Telegram напишите **@BotFather** → `/newbot` → имя → получите токен вида `8123456789:AAH...`.
2. Узнайте свой chat_id: напишите боту **@userinfobot** — он пришлёт `Id: 123456789`.
3. **Важно:** сначала сами напишите своему новому боту любое сообщение (`/start`), иначе Telegram не даст боту вам писать.

### 2.2. Запуск на компьютере / сервере

```bash
cd snowball-copy-bot
cp .env.example .env
nano .env          # вписать TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID
```

Проверка, что всё работает:

```bash
python3 bot.py --test-notify      # пришлёт «Проверка связи» в телеграм
python3 bot.py --dry-run          # покажет последние сделки в консоли, ничего не отправляя
python3 bot.py                    # рабочий режим (Ctrl+C — остановить)
```

Tребования: Python 3.9+ и всё. На Windows вместо `python3` — `python`.

### 2.3. GitHub Actions — вообще без своего сервера (рекомендуется)

Всё уже настроено: workflow лежит в `.github/workflows/snowball-bot.yml` и запускается каждые 10 минут. Состояние («что уже отправлено») хранится в `state/state.json` и коммитится обратно в репозиторий, поэтому дублей не будет.

Что нужно сделать один раз:

1. Создать репозиторий (лучше **публичный** — тогда минуты Actions бесплатны без лимита; в приватном 2000 мин/мес, а бот тратит ~2500 при опросе раз в 10 минут — для приватного поставьте cron `*/30 * * * *`).
2. Добавить два секрета: **Settings → Secrets and variables → Actions → New repository secret**
   - `TELEGRAM_BOT_TOKEN` — токен от @BotFather;
   - `TELEGRAM_CHAT_ID` — ваш id (от @userinfobot). Несколько получателей — через запятую.
3. Проверить связь: вкладка **Actions → «Проверка связи (Telegram)» → Run workflow**. В Telegram придёт «Проверка связи».
4. Проверка на реальных данных: **Actions → «Snowball copy bot» → Run workflow**, поле `send_last` = `5` — бот пришлёт 5 последних сделок портфеля, даже если они уже были отмечены как просмотренные. Дальше плановые запуски присылают **только новое** (первый плановый запуск молча запоминает всю историю, чтобы не выстрелить 4000 сообщениями).

Полезное:

- `dry_run: true` в ручном запуске — покажет сообщение в логе, ничего не отправляя (удобно после смены настроек).
- `send_last` можно использовать сколько угодно раз — это тестовый режим, он не ломает основной учёт.
- Настройки фильтров правятся прямо в workflow в блоке `env:` (`ONLY_TYPE`, `MIN_AMOUNT`, `COPY_SCALE`, `ASSET_DETAILS`, `IGNORE_TICKERS`).
- Расписание GitHub неточное: при запуске «каждые 10 минут» реальная задержка обычно 2–15 минут. Для сигналов с задержкой на публикацию сделки это не критично, но знать стоит.
- Секреты в логах маскируются; в репозитории их нет — только в Secrets.
- Если 60 дней не будет никакой активности в репозитории, GitHub выключит расписание — но бот сам коммитит состояние при новых сделках, так что активность есть. На всякий случай можно раз в месяц нажать Run workflow вручную.

### 2.4. Автозапуск на сервере (systemd, Linux VPS)

```bash
sudo cp deploy/snowball-copy-bot.service /etc/systemd/system/
# поправьте в файле пользователя и путь, если проект лежит не в /opt/snowball-copy-bot
sudo systemctl daemon-reload
sudo systemctl enable --now snowball-copy-bot
sudo journalctl -u snowball-copy-bot -f     # смотреть логи
```

### 2.5. Cron на домашнем ПК / Raspberry Pi

Вместо постоянного процесса можно запускать проверку по расписанию — состояние хранится в базе, дублей не будет:

```cron
*/5 * * * * cd /home/user/snowball-copy-bot && /usr/bin/python3 bot.py --once >> data/cron.log 2>&1
```

### 2.6. Docker (если так удобнее)

```bash
docker build -t snowball-bot .
docker run -d --name snowball-bot --restart unless-stopped --env-file .env -v "$PWD/data:/app/data" snowball-bot
```

## 3. Настройки (`.env`)

| Переменная | Смысл |
|---|---|
| `PORTFOLIO_ID` | код публичного портфеля (по умолчанию `ukbRjaXjfg`) |
| `POLL_INTERVAL` | как часто проверять, сек (мин. 60, по умолчанию 300) |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | доставка в Telegram (chat_id можно несколько через запятую) |
| `MAX_BOT_TOKEN`, `MAX_USER_ID` / `MAX_CHAT_ID` | доставка в MAX |
| `ONLY_TYPE` | `buy` — только покупки, `sell` — только продажи, `both` — всё |
| `MIN_AMOUNT` | не присылать сделки меньше суммы, ₽ |
| `IGNORE_TICKERS` | список тикеров-исключений через запятую |
| `INCLUDE_INCOME` | присылать ещё и купоны/начисления |
| `COPY_SCALE` | пересчёт под ваш капитал: `0.1` = показывать, сколько купить вам при капитале в 10 раз меньше |
| `ASSET_DETAILS` | подтягивать цену/доходность/рейтинг бумаги (по умолчанию да) |
| `CHECK_QUALIFIED` | проверять доступность неквалу (MOEX + рейтинг) — по умолчанию включено |
| `ONLY_NO_TEST` | `1` — присылать только сделки, которые неквал может купить без теста (продажи проходят всегда) |
| `FIRST_RUN` | `baseline` — при первом запуске просто запомнить историю; `last:5` — прислать 5 последних сделок для проверки |
| `CONSOLE_OUTPUT` | дублировать сообщения в консоль |
| `STATE_BACKEND` | `sqlite` (сервер, файл `data/bot.sqlite3`) или `json` (GitHub Actions, файл `state/state.json`) |
| `STATE_PATH` | путь к JSON-состоянию (для `STATE_BACKEND=json`) |

### MAX (max.ru)

1. Создайте бота: **business.max.ru** → «Чат-боты» → создать → после модерации в «⋮ → Настройки» будет токен.
2. Напишите своему боту любое сообщение.
3. Узнать `user_id`: `curl -H "Authorization: ВАШ_ТОКЕН" "https://platform-api2.max.ru/updates"` — в ответе будет `sender.user_id`. Либо создайте группу, добавьте бота и отправьте сообщение — в том же ответе будет `chat_id`.
4. Впишите токен и id в `.env`. Если сервер в РФ и ругается на TLS — поставьте в систему сертификат Минцифры (документация MAX этого требует), либо используйте `MAX_API_BASE=https://botapi.max.ru`.

MAX-канал работает «только на отправку». Команды (`/status` и т. д.) реализованы для Telegram.

## 4. Как это устроено внутри

Бот использует те же публичные запросы, что и сайт Snowball (без логина):

```
GET https://snowball-income.com/extapi/api/public/transactions
    ?page=1&pageSize=100&sortBy=date&sortDirection=desc&filter=
    &portfolioId=ukbRjaXjfg
    &supportedTypes[]=1&supportedTypes[]=2&supportedTypes[]=4
Заголовки: X-Instance: ru, Accept-Language: ru, x-user-locale: ru-RU, x-device-type: desktop
```

Типы операций: `1` — покупка, `2` — продажа, `4` — обмен, `5` — начисления (купоны/дивиденды).
Для карточки бумаги используется `/_next/data/<buildId>/public/asset/<TICKER>.MCX.RUB.json`; `buildId` берётся со страницы автоматически и кэшируется, поэтому после обновления сайта бот сам «переучивается».

Если Snowball поменяет формат API, бот начнёт писать в лог ошибки и один раз пришлёт предупреждение — тогда нужно поправить `snowball_bot/api.py`.

## 5. Реальность: что именно вы собираетесь копировать

Я посмотрел на данные портфеля на 17.11.2026 — и это важно понимать до запуска.

**Портфель очень активный.**

| Показатель | Значение |
|---|---|
| Всего сделок в истории | 4 003 |
| Сделок за последние 20 дней | 117 (≈ **7 в день**) |
| Медианная сделка | ≈ 84 000 ₽ |
| Покупок за 20 дней | 73 на 5,5 млн ₽ |
| Продаж за 20 дней | 44 на 4,4 млн ₽ |
| Разных выпусков за 20 дней | 62 |
| Из них и покупались, и продавались | 15 (активная торговля, не «купил и держи») |

**Бумаги — высокорисковые ВДО.** Из 52 выпусков, торговавшихся в последние дни: у 21 доходность к погашению выше 30 %, у 14 цена ниже 80 % от номинала, а у части — уже дефолтная (например, СибСульфур БО-02-001P торгуется по ~22 % от номинала при «доходности» 480 % — это не доходность, а сигнал о проблемах эмитента). Кредитных рейтингов у этих выпусков, как правило, нет.

**Вы — неквалифицированный инвестор, а значит:**

- облигации с рейтингом **A+ и выше** (а также ОФЗ и субфедеральные) покупаются без теста;
- облигации **без рейтинга или с рейтингом ниже** — только после тестирования у брокера (тест бесплатный, пересдавать можно сколько угодно, действует на конкретный тип инструментов у конкретного брокера);
- если тест не сдан — работает «право последнего слова»: сделка до **100 000 ₽** (или один лот, если он дороже). Именно по этой причине у большинства сделок в портфеле размер ~50–100 тыс. ₽ — автор, судя по всему, тоже упирается в лимиты;
- часть выпусков может быть вообще закрыта для неквалов — тогда никакой бот не поможет, заявку отклонит брокер. Проверять надо в приложении брокера по конкретному ISIN, а не по названию.

**Почему я бы не делал из этого «полный автокопир»:**

1. Семь сделок в день — это не инвестирование, а скальпинг спреда. Между публикацией сделки на Snowball и вашей заявкой проходит от нескольких минут до получаса; в ВДО спред легко съедает 1–3 % — вся «идея» сделки к этому моменту уже отработана.
2. Часть сделок — покупки падающих бумаг, у которых цена уже ниже 30 % от номинала: если копировать вслепую, вы просто покупаете чужой риск.
3. Комиссии и НКД: уважать НКД вы будете платить полностью, а заработать на нём же сможете только при продаже.
4. Требуется тест у брокера на большинство этих выпусков, и всё равно останется лимит 100 тыс. ₽ на сделку без теста.
5. Автор ведёт публичный портфель как трекер (в т. ч. для сообщества) — мотивация и сроки его сделок вам неизвестны, а состав меняется каждый день.

**Что бот даёт по факту:** вы видите логику живого трейдера и его результаты в реальном времени, можете выборочно повторить 1–2 идеи в месяц после сдачи теста, а не механически копировать всё. Это ровно то, что вы просили (уведомления), и это разумный вариант. У бота есть переключатель `ONLY_TYPE=buy` и `MIN_AMOUNT` — удобно отсечь мелкие продажи и смотреть только на покупки.

## 6. Что можно добавить дальше

- **Автопокупка через Т-Инвестиции API** (у неквалов API работает): по сигналу бота выставлять лимитную заявку на N лотов с ограничением дневного бюджета. Реализуемо, но требует токена брокера и отдельного «предохранителя» — без него автоторговля чужими сигналами кончается плохо.
- Фильтр качества: не присылать бумаги с ценой ниже X % от номинала / с YTM выше N % (сейчас бот только предупреждает).
- Дайджест «что автор купил за неделю и как это себя чувствует» — раз в неделю по расписанию.
- Веб-панель со списком сделок и кнопкой «повторить в брокере».

## 7. Дисклеймер

Бот — инструмент информирования, а не инвестиционная рекомендация. Он не гарантирует полноту и своевременность данных (источник — публичная страница Snowball, задержки и изменения формата возможны). Решения о сделках принимаете вы; ответственность за результат — тоже ваша. Перед покупкой ВДО проверьте выпуск в приложении брокера: доступен ли он неквалу, какой рейтинг, нет ли сообщений о дефолте/техническом дефолте.
